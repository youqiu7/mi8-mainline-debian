## 2. 根因链终版（8 环，从 wlan0 不存在倒推）

```
① rmtfs 内核驱动缺失（=m 且无 /lib/modules）→ MPSS 读 EFS 共享内存 0xf6301000 被 TZ 拦
   → 解：rmtfs_auth.ko（qcom_scm_assign_mem，返回 0 实证授权成功）
② rmtfs 服务 enumerate 按节点名 rmtfs* 前缀匹配（本机叫 memory@f6301000）→ mmap EINVAL
   → 解：三补丁版 rmtfs（compatible 匹配 + fsg_oem 表 + 逐字节拷贝修 SIGBUS）
③ EFS 数据缺失 → mpss 读 superblock 后自杀 → 解：sdf6/7（modemst LUN）原厂提取
④ MPSS 固件配对：firmware-qcom-soc 通用 modem + 通用 wlanmdsp（3,725,044B）组合下
   wlanfw 校验不过 → 解：bk_modem 分区全原厂三件套（mba/modem.b00-28/wlanmdsp 2021）
⑤ tqftpserv 路径：modem 请求 /readonly/vendor/firmware/* 被拒 → translate 落
   /lib/firmware/qcom/sdm845/polaris/（与 modem.mbn 同目录）→ 解：wlanmdsp.mbn 放此
⑥ wlanfw（QRTR svc=0x45）注册 → ath10k-qmi server arrive
⑦ ath10k_snoc probe（cold-boot 供电 + fw 加载）→ wlan0
⑧ udevd 缺件 → device unit/networkd/wpa 感知断裂 → 解：apt 装 udev + enable 两个 socket
```

## 4. 新踩的坑（并入 24 号手册族）

1. **`echo stop > remoteproc0/state` → 整机重启（3/3 复现）**：modem stop 触发硬重启（疑似 watchdog 级联）。规避：要重启 modem 就整机 reboot（更干净）。
2. **cp 后不 sync 遇硬重启 = 写丢失**（16:10 的 wlanmdsp 覆盖被随后的重启吞掉，文件回到旧内容）。铁律：**固件类写入后 `sync`**。
3. **`systemd-udevd` 可能根本没装**（debootstrap 变体缺件）：症状=一切"热插拔感知"失灵（device unit 永 inactive、networkd 不识新接口），/dev 却正常（devtmpfs 兜底）——极具迷惑性。`udevadm` 不存在即确诊。
4. **`systemd-modules-load` 在本内核不可用**（"Failed to initialize libkmod context: Operation not supported"）——自定义模块必须走服务 ExecStartPre。
5. **wlanmdsp.mbn 版本配对**：modem RRQ 的 `rsize` 字段=它期望的固件大小，是判定配对关系的显微镜（我们：3,725,044=linux-firmware 通用版 vs 3,645,892=本机 2021 原厂版，原厂三件套组合才过）。
6. Windows 侧 NCM 适配器会拿到 10.55.0.x DHCP 租约——SSH 连接地址 `10.55.0.1` 与 `169.254.1.1` 双备。
7. WSL MSYS 多层转义（`$((`、三引号嵌套）本轮又踩 3 次——复杂命令一律脚本文件。
