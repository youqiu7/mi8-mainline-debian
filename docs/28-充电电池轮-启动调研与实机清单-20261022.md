# 28-充电电池轮-启动调研与实机清单-20261022

> 时间：2026-10-22 02:00（CST）· 主会话（屏幕轮挂死等待期间的离线准备）
> 状态：**离线调研完成，实机取证待设备恢复**（用户队列第 2 项；与屏幕 v2 合并进同一版 EFI 的"统一刷写轮"）

## 1. 已知事实（历史取证）

- 电池 3000mAh；**Android 时代电量可读**（`battery/capacity` = 89%，02号§5）——硬件/PMIC 本身健康
- 电量计 IC：**bq27xxx 系**（02号 grep 实证；主线 `bq27xxx_battery_i2c.c` 在 ✓）
- 充电 IC：PMI8998 的 QPNP SMBB/SMBC 外设（SDM845 标准配置）
- Debian 现状：`/sys/class/power_supply/` 大概率空壳或仅剩无线充电/无节点——**待实机确认**

## 2. 主线驱动清单（6.19.14 树实测）

| 驱动 | 路径 | 作用 |
|---|---|---|
| `qcom_smbb.c` | drivers/power/supply/ | QPNP SMBB 充电器（PMI8998 chgr 外设） |

## 3. 修复路线假设（与屏幕轮同构，风险低）

1. **实机取证**（设备恢复后，15 分钟）：
   ```bash
   # FdtBlob 的充电节点
   ls /proc/device-tree/soc@0/spmi@*/qcom,pmi8998*/ | head
   grep -r . /proc/device-tree/soc@0/spmi*/**/compatible 2>/dev/null | grep -iE 'charg|batt|qg|bq27|smb'
   ls /sys/bus/spmi/devices/ /sys/bus/i2c/devices/ | head -20
   ls /sys/class/power_supply/
   dmesg | grep -iE 'smb|charg|batt|qg|bq27'
   ```
2. **决策树**：
   - FdtBlob 节点 compatible 与主线匹配 → **只开 config**（QCOM_SMbb/POWER_SUPPLY/BATTMGR/BQ27XXX=y）重编
   - compatible 不匹配 → 驱动加 of_match 行（面板同款一行改动，零 dtb 风险）
   - 节点缺失（FdtBlob 不含充电子树——低概率，PMIC 是系统骨架）→ 从 vendor-full.dts 抄节点做 dtb 扩展（高风险路线，FV 扩 F——排最后）
3. **合并进统一刷写轮**：屏幕 v2（去 RDID 提前）+ 充电 config/驱动 → 一次重编一次刷写。

## 6. 首轮实机结果 + 社区弹药重大改观（2026-10-22，v4 实验 + sdm845-mainline 调研）

**实机**：
- **FdtBlob 全树无 charger/fg/batt 节点**（vendor 用 devcfg 静态 SPMI 外设表）→ `/sys/class/power_supply/` 为空（当前 #48 实测确认 total 0）。
- mainline `pmi8998.dtsi` 自带 `qcom,pmi8998-charger` 节点且副会话 dtb 已包含——但 **appended dtb 未生效**（29号铁律），真 DT=UEFI FdtBlob（无 charger）。
- v4（config +`CHARGER_QCOM_SMBB=y`）挂死——**但复核 compatible：老 SMBB 不 match `qcom,pmi8998-charger`**（挂死的 SMBB 假说存疑，v6 clang 二分实验判定中）。

**社区弹药**（gitlab sdm845-mainline，sdm845-6.18.2-r0 已浅 clone 到 scratch/sdm845-linux）：
1. **正确驱动=mainline `CHARGER_QCOM_SMB2`（qcom_smbx.c，6.16+）**——实测 match `qcom,pmi8998-charger` ✓（我们 6.19 树内已有该驱动与 compatible）。
2. **4 台 sdm845 设备启用先例**（分支 `b4/pmi8998-charger-dts`，2023）：oneplus×2 / shift-axolotl（**含 smb1355 并联充电节点——smb1355 主线有启用先例**）/**xiaomi-beryllium**（家族先例）。关键认知：**bootloader 限制 500mA，启用 pmi8998-charger 才解锁正常充电速度**。
3. **电量计有解**：社区 6.18 分支带 `CONFIG_BATTERY_QCOM_FG=m`（qcom_fg.c，fg-gen3 移植补丁，Joel Selvaraj）——6.19 主线无此文件，**需 cherry-pick**。
4. 社区 sdm845.config 是全量参考金矿（充电/相机/触摸 config 齐活）。
5. **最终启用姿势已确认极简**（6.18.2 主线 beryllium-common.dtsi 428-461 行，已合并）：
```dts
&pmi8998_charger {
	monitored-battery = <&battery>;
	status = "okay";
};
&pmi8998_fg {
	status = "okay";
	power-supplies = <&pmi8998_charger>;
	monitored-battery = <&battery>;
};
```
即充电+电量计的 dts 改动总共 9 行（simple-battery 节点已有）。**待核对**：6.19 树的 fg 驱动文件名（6.18 config 有 BATTERY_QCOM_FG=m，6.19 树无 qcom_fg.c——联调时确认驱动文件名/是否改名）。

**下一轮执行序**（fdtoverlay/FV 路线承载 dts 属性）：① v6 判定编译器 → ② SMB2=y + 对照 beryllium/oneplus commit 补全 charger 节点属性（vbus-supply/中断/电池属性）→ ③ smb1355 并联节点评估 → ④ cherry-pick qcom_fg 补丁实现电量可见性。PMIC 硬件本身健康（USB 下自主充电；Android 时代 capacity 89% 可读）。

- `/sys/class/power_supply/battery/`：capacity/status/voltage_now 实时更新
- 插电（若有充电器）：status = Charging，current_now 有值
- 电量随时间变化合理（不虚标）
