## 2. 双战线结论（一句话版）

主摄 IMX363 + IR OV9282 + 副摄 S5K3M3（探测框架）三路都推进到 **“软件全绿、sensor i2c 不应答”**；EEPROM/actuator（不需要 XVCLK、不用 DVDD）全部应答。**物理待测两项**（需万用表/20元 USB 逻辑分析仪）：

1. **gpio99 使能的 DVDD rail（1.35V）物理输出**——三摄共用的唯一电源，最高嫌疑（37号§10 证据链）
2. XVCLK pin13/14/16 物理 24MHz 输出（v46 已手动 prepare PLL2 480M→src 24M 全绿仍 NACK，次嫌疑）

**测量动作**：v46 上 `echo 16-0010 > /sys/bus/i2c/drivers/imx363/bind` 触发 8s 窗口（MCLK+供电保持），万用表测：gpio99 对应 LDO 输出电容、pin13 电平；逻辑分析仪直接看 pin13 24MHz + I2C 波形。

## 3. 重启任务三步

1. **硬件判决后**：DVDD 问题→查板上该 LDO 的输入/使能链（或 DT 换供电脚）；MCLK 问题→patch pinctrl-msm8998（fs 表）或 camcc（MCLK branch prepare 链）
2. **撤诊断 hack 出正式版**：删 imx363.c/ov9282.c 里的 `MI8 FSSCAN/MI8 WINDOW/MI8 IRWIN/MI8 PLL(parent)` 打印与 msleep（文件已存档，恢复=从锚点取社区原版 imx363.c + mainline revert ov9282.c 或手工删段）；chip ID 0x0363/0x9282 读出后 → media-ctl -p → v4l2-ctl RDI 抓帧（非全零判据）；libcamera 无这两款 tuning，画质 raw/灰度级（fajita 先例）

## 5. 关键知识速查（重启免重挖）

- **Qcom CCI**：`drivers/i2c/busses/i2c-qcom-cci.c`（CONFIG_I2C_QCOM_CCI）；cci i2c-bus@0=adapter i2c-16、bus@1=i2c-17
- **camcc MCLK**：24M 源=PLL2_OUT_EVEN（freq_tbl）；**手动开**=clk_get_parent 链 prepare（v46 hack）；assigned-clock 配 **src 端**（0x43=MCLK0_SRC/0x45=MCLK1_SRC/0x49=MCLK3_SRC），配 mux 端报 "Error applying setting"
- **TITAN_TOP GDSC index=5**（camcc PD enum，非 BCR index 9）；sensor power-domains=<0xc2 0x05>（fajita 惯例）
- **tlmm**：pin N cfg=base+0x1000×N（pin13=0x340D000，fs=bit[2:0]，cam_mclk=fs1 与 vendor 一致）；**/dev/mem 读 io 区必硬挂**（红线）
- **四摄接线**（vendor-full 权威）：主摄 MCLK0/p13/rst80/AVDD=L22/DVDD=g99；IR MCLK1/p14/rst25/AVDD=tlmm27 3.3V/DVDD=g99/addr0x60；副摄 MCLK3/p16/rst28/AVDD=BOB(boot 即 3.33V)/DVDD=g99/i2c-17；前摄 MCLK2/p15/rst104（未测）
- **驱动 supply 名**：imx363=vif/vana/vdig；ov9282=avdd/dovdd/dvdd（inclk 必须恰好 24M，2-lane，link-freq 400M）
