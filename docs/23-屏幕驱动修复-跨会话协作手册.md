## 1. 环境搭建（WSL Ubuntu，你的专属环境）

```bash
# 1) 工具链
sudo apt-get update && sudo apt-get install -y build-essential bc bison flex libssl-dev \
    libelf-dev dwarves python3 git rsync kmod file u-boot-tools
# aarch64 交叉编译器（Ubuntu 包名）
sudo apt-get install -y gcc-aarch64-linux-gnu
# dtc
sudo apt-get install -y device-tree-compiler
# 2) 内核源码：与主会话同一份 6.19.14 的独立解包（Windows 共享盘里读）
mkdir -p /root/k619u && cd /root/k619u
tar xf "/mnt/f/小米刷机/dagu移植debian/k619/k619.tar"    # 若 tar 内已含 linux-6.19.14/ 目录则无需再挪
# 3) .config 基线（主会话已交付）
cp "/mnt/f/小米刷机/米8移植debian/05-跨会话/04-交付-主集成/config-6.19.14-baseline.config" \
   /root/k619u/linux-6.19.14/.config
cd /root/k619u/linux-6.19.14 && make ARCH=arm64 olddefconfig
```

**铁律**：你的树在 `/root/k619u/`（Ubuntu WSL）；主会话的树在 **WSL Debian** 实例的 `/root/k619/`——两实例文件系统天然隔离，但**谁都不要去对方实例里写东西**。共享只经 Windows 盘 `F:\小米刷机\米8移植debian\05-跨会话\`。

编译命令（每次都要带，漏了会报 "No rule to make target"）：
```bash
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc) dtbs          # 只编 dtb：秒级
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc) Image modules  # 全量：约 10-30 分钟
```
⚠ **两个 WSL 实例共享同一台 Windows 的 CPU/内存**：你编译期间主会话可能也在跑重活，`-j` 不要超过 `$(nproc)/2`，避免互相拖死。

4. **节奏**：每完成一个 P 阶段（见 §5）更新一次 STATUS；卡点超过 2 轮自查未解 → 在 STATUS 里写明"需要主会话做什么"（附具体命令/文件），然后继续其他可推进项，不空转。

## 5. 任务分解（P0 → P4）

### P0 现状取证（SSH 只读，不改任何东西）
```bash
dmesg | grep -iE 'simplefb|efifb|msm|drm|dsi|panel|framebuffer' 
ls /sys/class/graphics/ /sys/class/drm/ 2>/dev/null
ls /sys/firmware/devicetree/base/soc@0/ | grep -iE 'ae00000|ae940000|display'   # mdss/dsi 节点存在性
cat /proc/fb 2>/dev/null; ls /sys/class/backlight/ 2>/dev/null
```
把输出存到 `03-交付-副显示\P0-现状取证-副-<时间>.txt`。**判断**：当前是 simplefb 控制台（屏幕可能亮着 logo/雪花）还是完全无输出。

### P1 面板驱动移植（核心）
- 参考实现：**woaiyuzi/linux**（GitHub，6.5-rc4，作者内核）`drivers/gpu/drm/panel/panel-samsung-ea8074.c`，其 notch 变体结构体 `ss_notch_fhd_ea8074` 与本机面板 porch **逐项吻合**（hfp56/hbp56/hpw18/vfp26/vbp24/vpw12/60Hz，02号§10.3 已核对）。
- **已知必改 bug**（02号§10.3）：该驱动 `dsi->mode_flags` 设成了 **video mode**（`MIPI_DSI_MODE_VIDEO_BURST`），而本机面板是 **cmd mode**（vendor DT `dsi_cmd_mode`）。改法：去掉 `MIPI_DSI_MODE_VIDEO_BURST`，保留 `MIPI_DSI_CLOCK_NON_CONTINUOUS | MIPI_DSI_MODE_LPM`，并补 **TE 同步**（panel init 加 `MIPI_DSI_MODE_CMD_MODE`? 主线写法：用 `MIPI_DSI_MODE_VIDEO` 不加即为 cmd；TE 由 `MIPI_DSI_MODE_CMD_USE_TE` 或 panel prepare 里 request GPIO IRQ——上游同类 cmd panel 参考 `panel-samsung-s6e3fc2x01.c` 的写法）。
- 面板参数源（**以本机提取为准，勿凭记忆**）：`01-资料\dtree-panel-ea8074-notch.dts`（123 行，含 ~40 条 on-command 初始化序列、reset-sequence `<1 1 0 1 1 10>`、背光 DCS 0x02–0x3ff、t-clk 0x34/0x0e）。
- 落地：驱动放 `drivers/gpu/drm/panel/panel-samsung-ea8074.c` + Kconfig/Makefile 两行 + 你树里的 config 开 `CONFIG_DRM_PANEL_SAMSUNG_EA8074=y`（自建 Kconfig 名）。**先只求点亮**：初始化序列可以整段照搬 vendor on-command。

### P2 dts 接线（panel + 触摸 + 背光）
新建/修改你的 dtb 基线（主会话当前用的是 UEFI 内嵌的 **polaris dtb**，103382B，来源 edk2-msm FdtBlob；你以 WSL 树的 `arch/arm64/boot/dts/qcom/sdm845-xiaomi-polaris.dts` + sdm845.dtsi 为底，**最终交付 dtb**）：
- `&dsi0` 挂 panel：compatible 用你移植驱动的 compatible；`panel-timing` 用 §P1 的参数；`reset-gpios = <&tlmm 6 ...>`；**TE：`&tlmm 10`**（cmd mode 必需，dipper/上游 dts 没有——必须自己加）；backlight 节点（`backlight` compatible=panel 或 `pwm`？本机是 **DCS 背光**：用 `compatible = "pwm-backlight"` 不对——DCS 用 panel 自带 backlight 属性：`backlight = <&panel_backlight>`，节点 `compatible = "pwm-backlight"` 是错的；主线 cmd panel DCS 背光直接在 panel 驱动里做，dts 可省 backlight 节点或用 `simple-backlight`——**以 woaiyuzi 驱动的实际实现为准**，它若自管背光则 dts 不加）。
- 触摸：`&i2c14`（`i2c@a98000`）下加节点 reg=0x49、`compatible = "st,fts"`、中断 `<&tlmm 31 IRQ_TYPE_EDGE_FALLING>`、`reset-gpios = <&tlmm 32 GPIO_ACTIVE_LOW>`、供电 `vdd-supply`/`avdd-supply`（对照 vendor：`01-资料\dtree-touch-fts.dts` 31 行；dipper 用 `vreg_l14a_1p8`，注意核对 avdd）。**主线 `stmfts.c` 只认 `st,stmfts`**（6.19 树 line 785）→ **加一行 of_match `{ .compatible = "st,fts" }`**（这是最省力的一处，02号§4 结论）。
- 原始素材：`01-资料\vendor-full.dts`（26,125 行全量 vendor DT）里可搜 `dsi_ss_ea8074`、`fts@49`、pinctrl `pmx_ts_active` 等照抄。
- 验证方式（离线）：`make dtbs` 后 `dtc -I dtb -O dts` 反编译自查节点存在、无 phandle 悬空。

### P3 与显示栈的关系（config 层）
- 需要开：`CONFIG_DRM_MSM`、`CONFIG_DRM_PANEL_*`（你新加的）、`CONFIG_DRM_MIPI_DSI`、`CONFIG_DRM_FBDEV_EMULATION`、`CONFIG_BACKLIGHT_CLASS_DEVICE`。
- **simplefb 与 msm-drm 并存问题**：UEFI 会注入 simple-framedevice（可能已在跑 simplefb）。msm-drm 起来后抢 fb0——共存通常无害；若卡住可后期内核 cmdline 加 `simplefb.enabled=0`（交给主会话改 ESP cmdline 时再说，先不管）。
- 产出 config diff：`diff .config基线 .config新 > config-display.patch`。

### P4 交付（给主会话刷写）
放 `03-交付-副显示\`：
1. `dtb-polaris-display-副-<时间>.dtb`（你编出的成品 dtb，**必须**能在 WSL `dtc` 反编译回来）；
2. `panel+touch+config-副-<时间>.patch`（对内核树的完整 diff，含驱动文件新增）；
3. `README-刷写与验证清单-副-<时间>.md`：主会话要执行的步骤（刷 dtb 进 UEFI FV 的工具链主会话已具备——见 21号§4 解包链；或主会话重编 UEFI FV）、上机后**验证命令清单**（dmesg 预期行、`ls /sys/class/drm`、背光节点、`evtest` 触摸）、**回滚说明**（恢复锚点 boot-equuleus.img 即回旧状态）。
4. 在 `02-副发主\STATUS-副显示.md` 顶更新"交付待刷写"。

## 7. 已知坑位速查

| 坑 | 说明 |
|---|---|
| woaiyuzi 驱动是 video mode | 本机 cmd 面板，必改（§P1），否则黑屏/花屏 |
| TE GPIO10 缺失 | cmd mode 必需，上游 dts 没有，必须加 |
| 触摸 compatible 一行之差 | `st,fts`（本机）vs `st,stmfts`（主线）——改驱动 of_match 比改 DT 好（DT compatible 是硬件真实值） |
| 触摸固件 st_fts_e8.ftb | vendor 分区里没有，疑似烧在 IC 里；stmfts 无固件也能出事件，先不纠结 |
| make 忘 ARCH/CROSS_COMPILE | 必报 No rule to make target |
| Kconfig 出现 NEW 选项卡死 | `make ARCH=arm64 olddefconfig` 自动填充，别裸跑 make 等交互 |
| WSL 编译被回收 | 不要 nohup 后台跑，单次前台完成；用户消息会打断编译 |
| 分辨率 1080×2248 | hsync/vsync 数值含 porch，抄 §P1 表格，别自己算 |
| 电源（电池未修）| 边充边测，掉线先查电 |
