**dtbo 与 vbmeta 分区实测为空：**
```bash
$ # dtbo = 8 MiB, vbmeta = 128 KiB, 全部读出后统计非零字节
dtbo   : nonzero 0 / 8388608   (DTBO magic 0xd7b7ab1e 未出现, FDT magic 0xd00dfeed 未出现)
```

## 7. boot.img 头部实测（打包器的依据）

```bash
$ dd if=/dev/block/by-name/boot of=/sdcard/boot.bin bs=1M count=1
$ python 02-工具/boot_hdr.py boot_head.bin
magic=ANDROID!
kernel_size=44499364 (0x2a701a4) @0x8000     ← gzip 压缩（1f 8b 08 00）
ramdisk_size=1105166 (0x10dd0e) @0x1000000
second_size=0 @0xf00000
tags_addr=0x100  page_size=4096  header_version=1
os_version=0x1400014c  name=''
recovery_dtbo_size=0  recovery_dtbo_offset=0  header_size=1648
cmdline=console=ttyMSM0,115200n8 earlycon=msm_geni_serial,0xA84000 androidboot.hardware=qcom
        androidboot.console=ttyMSM0 video=vfb:640x400,bpp=32,memsize=3072000 ... buildvariant=user
payload_end = 45613056 (0x2b80000)
```

- **header v1、page 4096、无 second、无 dtb、kernel 为 gzip**
- 尾部从 `0x2b80000` 起有 **DER 结构（`30 82 05 24 …`）= AVB 签名块**，剩余空间全 0，直到分区末尾 64 MiB
  → 我们重打包的镜像不带签名，因 vbmeta 已空，**不影响引导**
- **与 Nura 主线指南给出的 mkbootimg 参数逐项吻合**：`base 0x0 / kernel_offset 0x8000 / ramdisk_offset 0x1000000 / tags_offset 0x100 / pagesize 4096 / second_offset 0xf00000`

### 打包器往返验证（已完成）
```
原厂 boot 64 MiB → unpack(kernel 44,499,364 B, ramdisk 1,105,166 B) → pack
比对前 45,613,056 字节：仅 header[576:608] 的 id 字段（20 字节 SHA-1）不同
header 其余 1628 字节 + kernel + ramdisk：逐字节一致
```
id 字段 bootloader 不校验，属纯元数据差异。

### 10.3 ⚠️ 面板驱动比对：可以用，但有一处疑似 bug

`woaiyuzi/linux` 的 `panel-samsung-ea8074.c`：

```c
.clock = (1080 + 56 + 18 + 56) * (2248 + 26 + 12 + 24) * 60 / 1000,   // ← 与本机 notch 面板逐项吻合
.hsync_start = 1080 + 56;  .hsync_end = 1080 + 56 + 18;
.vsync_start = 2248 + 26;  .vsync_end = 2248 + 26 + 12;
```
porch 值 **hfp56/hbp56/hpw18/vfp26/vbp24/vpw12/60Hz 全部一致**，结构体名也叫 `ss_notch_fhd_ea8074`
→ **这是给 notch 变体写的驱动，可以直接用**。

但它把 DSI 模式设成了 **video**：
```c
dsi->mode_flags = MIPI_DSI_MODE_VIDEO_BURST | MIPI_DSI_CLOCK_NON_CONTINUOUS | MIPI_DSI_MODE_LPM;
```
而 vendor DT 明确是 **`dsi_cmd_mode`**。cmd 面板在 video 模式下通常表现为黑屏或花屏。
**P2 第一件要试的事**：改成 cmd mode（去掉 `MIPI_DSI_MODE_VIDEO_BURST`，保留 `MIPI_DSI_CLOCK_NON_CONTINUOUS`），并补上 TE GPIO 10 的处理。
