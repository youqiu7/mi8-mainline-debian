# 39号｜充电轮 — v53b 全通 + 阈值守护（2026-10-24 03:20）

> **一句话**：SMB2 charger + PMI8998 FG 一轮全通（capacity 16% 实时可读），ICL 限流实测有效，mi8-charge-guard 阈值守护上线（<20% 开充 372mA、>80% 停充微补 14mA，USB 直供）。内核=**v53b**（8db9d107）。

## 需求（用户）

长期插电作服务器：**USB 直供电 + 电量低于阈值才开充、高于阈值停充**。

## 实现

| 层 | 内容 | 状态 |
|---|---|---|
| 内核 | CHARGER_QCOM_SMB2=y（qcom_smbx.c）+ BATTERY_QCOM_FG=y（**从社区 sdm845-linux cherry-pick qcom_fg.c**，6.19 主线无此驱动）+ QCOM_SPMI_RRADC=y | v53b ✓ |
| DT | **PMI8998 的 pmic@2 段注入三节点**：charger@1000（interrupts+io-channels rradc 3/4+monitored-battery）+ adc@4500（rradc）+ fuel-gauge@4000（interrupts soc-delta+power-supplies）+ 根级 simple-battery（phandle f21） | dtb= 机制 ✓ |
| 控制口 | smbx 的 **current_max（ICL）可写实测有效**：写 500000=充 372mA；写 50000=充 14.6mA（微补≈停充）；写 0 被拒；>500000 被 clamp | ✓ |
| 守护 | **mi8-charge-guard.service**：30s 轮询 qcom-battery/capacity，<START 写 CHG_ICL、>END 写 IDLE_ICL；阈值可调 | systemd 自启 ✓ |

## 实测结果

```
power_supply: pmi8998-charger + qcom-battery
qcom-battery: capacity=16  voltage=3.84V  current_now 实时
插入 USB → status=Charging
守护: cap=16 < 20 → charging ON (ICL=500000) → 充电 372mA
>80% 时: ICL=50000 → 充电停止（14mA 微补自放电，系统负载由 USB 直供）
```

## 配置（用户可调）

```bash
# /etc/default/mi8-charge-guard
START=20        # 低于此电量开充
END=80          # 高于此电量停充
CHG_ICL=500000  # 开充电流（驱动 clamp 上限 500mA）
IDLE_ICL=50000  # 停充微补值
systemctl restart mi8-charge-guard
```

## 弯路与教训

1. **v53 第一版 dtc 失败**：注入点在 pmic@2 属性前（DT 语法 Properties precede subnodes）→ 插到首个子节点前
2. **SPMI_RRADC config 名错** → 正确名 **QCOM_SPMI_RRADC**
3. **qcom_fg.c 没编进**（Makefile sed 被 bash $() 展开毁了 121 行）→ python 修复 Makefile+正确插入 → fg 才 probe（**教训**：Makefile sed 一律 python，bash 转义不可靠——红线第 10 次变体）
4. **WSL 当日持续抽风**（bash 脚本零执行、stdout 丢、localhost 警告）→ 最终解法：**python 文件+单命令执行**+stderr 保留（2>&1）
5. **fg 的 psy 名=qcom-battery**（非 battery）——battery 节点不存在，读 capacity 走 qcom-battery
6. **ICL 上限 500mA**：bootloader 硬约束未被解锁（写更大被 clamp）——充电速度保守但服务器场景够用
7. **写 0 禁充不可行**（驱动拒），用 IDLE_ICL=50000 近似停充（14mA 微补=补偿电池自放电，系统负载由 USB 直供路径优先）

## 充满测试结果（10-24 11:30，28%→99% 全程）

- CC 段（31%→80%）：66 分钟，平均 994mA，**库仑积分 1093mAh**（997 去重采样点）vs 标称理论 1470mAh，**缺口 -25.6%**
- 两种解释（未定论）：①电池老化至 ~2200mAh/74% 健康度（2018 年机器，可能性大）②FG SOC 中段非线性+库仑漂移（每 1% 在 4.0V 附近本就大于均值）
- CV 段（99%）：3.9mA 涓流 @4.30V 持续很长时间，FG 的 Full 判定保守；服务器场景无影响（长期插电，80% 即停）
- 记录资产：/tmp/charge-test.log（设备，997 采样）、charge-test.sh（qdebs/）
- 测试后恢复：END=100→80、记录器已停、守护 active（98% 时正确进入 idle 微补 ICL=50000）
