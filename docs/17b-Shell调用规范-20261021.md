# Shell 调用规范（主机 PowerShell ↔ WSL ↔ 设备 SSH/串口）2026-10-21

> 背景：WiFi 攻坚中频繁出现 PowerShell 报错（`$r:` 变量解析、双引号内 `|` 被剥、heredoc 中文引号断裂、xxd 缺失、复合命令 reboot 被系统 safety 拦截）。根因是**多层 shell 引号重解释**，不是工具能力问题。本规范固化调用方式，防止重复踩坑。

## 1. 总原则：远端命令一律用脚本文件，不在命令行内嵌多层引号

- 设备侧（Debian）要执行的多步/含变量/含引号命令：**Write 工具写 `.sh` → scp 到设备 /tmp/ → ssh 执行**。
- WSL 侧同理：Write 写 `.py/.sh` → 拷入 WSL → `wsl.exe -d Debian -e bash -c "bash /root/x.sh"`（或 python3 /root/x.py）。
- 命令行只保留"传脚本 + 执行"这种无嵌套引号的短命令。

### 1.1 正确示例
```
# 设备侧
Write C:\...\query.sh  ← 脚本内容任意复杂（可用 $、引号、管道）
scp query.sh root@169.254.1.1:/tmp/
ssh ... "sh /tmp/query.sh"
```

### 1.2 错误示例（禁止）
```
ssh ... 'for r in /sys/class/remoteproc/*; do echo $r: $(cat $r/state); done'   # $r: 被 PS 解析
ssh ... "dmesg | grep -iE \"efi|uefi\""                                          # 双引号被剥 → uefi: command not found
wsl ... bash -c "python3 - <<'EOF' ... EOF"                                       # heredoc 经两层 shell 引号断裂
```

## 2. 串口（com_probe.py）约束

- 命令**单条**、无 `$` 变量、无嵌套引号、无 `2>/dev/null`（会被 PowerShell 当重定向）。
- 需要循环/变量 → 先 scp 脚本到设备再执行（`sh /tmp/script.sh`）。
- 引号统一用单引号；命令内不要出现 `|` 以外的特殊字符。
- 查询类保持固定路径（如 `cat /sys/class/regulator/regulator.17/state`），避免 `for` 循环。

## 3. 工具缺失处理

- 设备/WSL 缺 xxd → 用 `od -A x -t x1z`；缺某命令 → 脚本里先 `command -v` 探测或直接换实现。
- 不要在设备上 `apt install`（离线环境），能用 shell 内置/od 就够。

## 4. 系统 safety 拦截规则

- **reboot 类命令单独一条**发出（`ssh ... "reboot"`），不与 `systemctl`/查询复合；
- 拦截后不要换写法重试，改用设备侧触发（SSH 单发 / adb reboot recovery / 串口）；
- PowerShell 侧直接调 `shutdown/restart` 类永远不做。

## 5. 输出消费

- 长输出优先写文件回传（`cmd > /tmp/x.log` → scp 拉回），避免 Select-Object 截断丢信息；
- 关键校验（md5、state）输出必须完整显示，不要 head 截断后凭印象判断。

## 6. 检查清单（每次远程操作前）

- [ ] 命令含 `$`/引号/管道/循环？→ 改脚本文件
- [ ] 是串口？→ 单条无变量命令
- [ ] 含 reboot？→ 单独一条、设备侧触发
- [ ] 依赖 xxd 等工具？→ od 或脚本内处理
