## 0. 总体结论

**核心子系统全部有主线路径，可达"日常可用"**：引导/USB/SSH ✅已完成 → 显示+触摸+GPU（副会话，可行性高）→ WiFi（今日修复就绪）→ modem/移动数据（rmtfs 链修复就绪）→ 音频（codec 主线已有）→ 电池/充电（驱动主线已有，排期在 WiFi 后）。
**确定性缺口（不可行/长期）**：屏下指纹（无主线驱动）、NFC（无）、GPS（本机是 Broadcom 方案，非高通，主线无）、摄像头（camss 对 sdm845 支持薄弱，长期）、蓝牙（WCN3990-BT 走 SLIMBus，主线无 slimbus BT host，短期无解）。
**高风险项**：suspend/resume（RPMh 睡眠链，建议放最后单独攻坚）。

## 2. 可行性分级汇总

- **A 级（确定可完成）**：WiFi、modem 数据、显示、触摸、GPU、电源键、电池/充电、音频。
- **B 级（可完成但有不确定性）**：传感器（型号未实测）、suspend、rmnet 数据配置。
- **C 级（当前无路径，建议明确放弃）**：指纹、NFC、GPS(Broadcom)、摄像头、BT(SLIMBus)。

**按 A 级全做完的预期形态**：带触摸屏与 GPU 加速的 Debian 平板/小主机，可上网（WiFi/蜂窝）、有声音、能充电、可外接 USB 设备——除拍照/指纹/导航/BT 外，接近完整平板体验。

## 3. 关键风险与提醒

1. **所有显示相关改动都会动 boot 层**（dtb 内嵌于 UEFI FV，21号§4 有完整解包链）——刷写由主会话统一执行，锚点 boot-equuleus.img 为回滚底牌（03-备份/锚点-20261021-0520）。
2. **modem 健康是 QRTR 主干的前提**（21号）——任何依赖 qrtr 的子系统（GPS 无、但未来可能的 audio/sensor 远端）都受此影响。
3. **simplefb 与 msm-drm 的接管关系**需在屏幕会话中实测确认（当前可能有 framebuffer 可用，点亮 msm-drm 后再切）。
4. 内核树为同一份源码的两个独立解包（Debian/Ubuntu 各一份）——**禁止交叉写入**。
5. 设备电量低 + 电池未修：任何长时间实测先确认充电状态（21号§6）。

## 4. 建议排期（结合用户任务队列）

1. **今日**：WiFi 收尾（rmtfs 部署→wlan0→连网）。
2. **并行**：屏幕/触摸（副会话已启动）。
3. **接着**：电池/充电（用户指定队列第二项）→ 更新锚点。
4. **然后**：音频 → 传感器 → modem 数据（ModemManager/rmnet）。
5. **最后**：suspend 攻坚；放弃项正式记档。
