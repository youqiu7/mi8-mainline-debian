> 时间：2026-10-22 20:30 · 主会话（用户增派：音频+蓝牙也要修复）· 前期论证批次
> **共同好消息：两轮的主线驱动全部现成在树**（6.19.14 实测），缺的是 config + DT 生效（fdtoverlay/FV）+ 固件。

## A. 音频轮

### 树内家底（实测确认）
- codec：`sound/soc/codecs/wsa881x.c` ✓（smartpa，本机 vendor DT 有 wsa881x×4）+ `wcd934x.c` ✓（845 的 WCD codec）
- machine：**`sound/soc/qcom/sdm845.c`** ✓（主线原生 sdm845 声卡机器驱动——比 dipper 早期复用 db845c-sndcard 更正）
- 框架：bolero/lpass/swr-mstr 系（qdsp6 目录 ✓）

### 把握度
| 分项 | 把握度 | 依据 |
|---|---|---|
| 声卡注册（snd-card 出现） | **80%** | 驱动+machine 全在；dipper 是 mainline 音频工作的家族先例；剩=DT routing/codec dai link 与本机（4×wsa881x 扬声器布局）匹配 |
| 扬声器出声 | **70%** | wsa881x 固件（ES 音效固件 wsa881x 可能需要 fw——待查）+ I2S/TDM 时序（vendor DT 有完整配置可抄——**但受 29号铁律约束需 fdtoverlay**） |
| 听筒/耳机 | **65%** | 同上 |
| 麦克风 | **55%** | dagu 项目麦克风也未通（WCD9385 前科）——ADC 路径历来难 |
| UCM 配置 | **60%** | 需为 sdm845 声卡写 UCM（可参考 dagu 的 CS35L41 UCM 经验+社区 alsa-ucm-conf） |

### 执行序
1. `CONFIG_SND_SOC_SDM845=y` + wsa881x/wcd934x/bolero/lpass（对照社区 sdm845.config）
2. DT：sound 节点+codec dai link（fdtoverlay 或 FV）——参考 dipper dts 497-504 行起步
3. 验证链：/proc/asound/cards 出声卡 → aplay 测扬声器 → UCM 完善
4. 判据：扬声器播放测试音

## B. 蓝牙轮

### 树内家底（实测确认）
- 驱动：`drivers/bluetooth/hci_qca.c` ✓（**含 wcn3990**——grep 命中）+ `btqca.c` ✓
- DT：polaris.dts 626-635 行有完整 `bluetooth` 节点：`compatible="qcom,wcn3990-bt"`、**`firmware-name="polaris/crnv21.bin"`**（qca/ 子目录下）、vddio/vddxo/vddrf/vddch0 四路电源——**FdtBlob 里大概率有同款节点**（polaris 系，联调时 /proc/device-tree 验证）
- 固件：crnv21.bin（BT NVM）——**原厂 vendor 分区有**（或 linux-firmware 仓库的 qca/ 目录——联调时比对）

### 把握度
| 分项 | 把握度 | 依据 |
|---|---|---|
| HCI 设备出现（hci0） | **80%** | 驱动+DT+固件路径三要素主线齐备；wcn3990 与 WiFi 共芯片（WiFi 已通=芯片健康✓） |
| 扫描/配对（bluez） | **70%** | hci_qca 的 wcn3990 路径在社区 845 设备有工作先例（需确认固件版本匹配） |
| 音频（HFP/A2DP） | **50%** | 依赖音频轮的声卡先通（BT 音频=SCO/A2DP 走音频栈） |

### 执行序
1. config：BT_QCA=y + btqca + 蓝牙用户态（bluez）
2. 固件：crnv21.bin 放 /lib/firmware/qca/polaris/（从 vendor 提取或 linux-firmware）
3. DT：bluetooth 节点（fdtoverlay/FV——若 FdtBlob 已有则免）
4. 验证链：rfkill unblock → hci0 up → hcitool scan → bluetoothctl 配对
5. 判据：扫描到周边 BT 设备 + 配对成功

### 关键协同
- BT 与 WiFi 同芯片（wcn3990）——**WiFi 已全链修复=芯片/供电/固件加载机制全部验证过的**——BT 是同一片硅的另一 radios，地基已打
- BT 音频依赖音频轮——两轮可并行推进、音频先行

## C. 未知（诚实清单）

2. crnv21.bin 的固件版本匹配（原厂版 vs linux-firmware 版）
3. wsa881x 是否需要音效固件（ES 固件路径）
4. 本机 4×wsa881x 布局与 dts routing 的对应（vendor DT 有真值）
