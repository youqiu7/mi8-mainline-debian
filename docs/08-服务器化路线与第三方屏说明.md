## 二、第三方屏幕的硬约束

用户说明：**显示屏、触摸屏、屏下指纹模组均已换为第三方组件**。

影响：

1. **不能照抄原厂 DT 的面板配置**。原厂是 `ss_notch_fhd_ea8074`（三星 EA8074 cmd mode），第三方屏很可能是别的 IC。
2. 屏幕能不能亮，取决于 DSI 面板驱动匹配，**不是必要条件**（服务器用途）。
3. **真实型号必须从 Linux 下实际读寄存器**：
   - DSI 面板：读 `0x04` (RDID1) / `0xDA` (RDID2) / `0xDB` (RDID3)，或读 DSI 的 `0xA1` 读 DDB
   - 触摸：i2c 扫描 + 读 `0xA3`/`0x00` 之类 ID 寄存器
   - 屏下指纹：i2c/spi 上扫地址

**做法**：Linux 起来后，用 i2c-tools / 自写探测程序扫 i2c14（触摸）、i2c 上的指纹 IC，把真实型号记进 `01-资料/`，再补 DTS。

## 三、USB 约束（硬规则）

**永远保持 device/peripheral 模式，不做 host。**

- DTS：`&usb_1_dwc3 { dr_mode = "peripheral"; }` —— 不改
- init：只配 gadget（CDC-ACM 串口 + 可选 UMS），**不配 host 控制器**
- 目的：屏幕可能完全不工作，USB 串口是**唯一的调试通道**

内核 cmdline 里 `console=ttyGS0` 保证从开机第一行就看到日志。

### init v5 的行为

```
启动 → 挂 proc/sys/dev → 判断 sda23
   ├─ sda23 有 ext4 + /sbin/init → switch_root → 进 Debian
   └─ 否则 → 暴露 sda22/sda23 为 U 盘 + 串口诊断模式
```

## 五、设备开机后的执行序列

```
1. adb push BOOTAA64.EFI /data/local/tmp/
2. adb shell su -c "mount /dev/block/sda22 /mnt && cp /data/local/tmp/BOOTAA64.EFI /mnt/EFI/Boot/ && sync && umount /mnt"
3. adb reboot recovery          # → UEFI → 新内核
4. 串口确认 DT model 变成 equuleus
5. UMS 出现后，把 rootfs-2g.img 写入 sda23
6. 串口发 r 重启 → init v5 挂 sda23 → switch_root → Debian
7. 串口 getty 登录（root / equuleus）
8. 首启脚本自动 resize2fs 到 59 GB + 装 openssh
```

## 六、遗留风险

1. **`dtb=` 依赖 UEFI Secure Boot disabled**。如果日志出现 `Ignoring DTB from command line`，说明 edk2 报了 secureboot，需要退回「patch 内核让它不用 UEFI 的 DTB」。
2. **写 misc 分区的方式不可靠**（init v4 的 `u` 命令导致关机），已废弃，统一走 `adb reboot recovery`。
3. rootfs 首次 2 GB，需要首启 `resize2fs` 才能用满 59 GB。
