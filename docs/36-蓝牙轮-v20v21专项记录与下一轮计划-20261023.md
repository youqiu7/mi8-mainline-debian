## 2. 卡点定案（已破案 ✅ 2026-10-23 10:30）

**根因（社区定案，搜索命中）：BD 地址无效**——WCN3990 的 NVM（linux-firmware 通用版 crnv21.bin）里无烧录地址，芯片报垃圾值 `39:90:21:64:07:00` → 内核将其分类 **HCI_UNCONFIGURED** → 从 MGMT 完全隐藏（btmgmt "0 items"）+ HCIDEVUP 95 + init 静默失败 + DOWN RAW——**此前全部症状一个根因**。出处：taufderl/moarchy（FP4/WCN3990 逐字同症状+验证修复）+ Rushtfy/postMarketOS-sm-a72q（A72/WCN3990，boot race 症状+reload 方案）。

**修复（已验证，开机全自动）**：DT bluetooth 节点加 `local-bd-address = [02 11 22 33 44 55];`（hci_qca probe 原生读取；显示为 55:44:33:22:11:02=字节序反转惯例）——**走 dtb= 路线零内核重编**。验证链：setup completed → Index list 1 item → powered ssp br/edr le secure-conn → bluetoothctl list [default] → **扫描到几十台周边设备**。

**速度实验结论作废**（115200/1M 下载超时是真实约束但与根因无关；3.2M 保持）。"boot race"假说不需要——地址修好后 boot 早期（5.3s）setup 一次成功。

**教训**（用户已批）：卡点应先搜社区先例——本轮自转 2.5h/8 轮，搜索 5 分钟定案。

## 4. 本轮踩坑速查（全部已验证）

1. **`depends on X || !X` 恒真式陷阱**：X=m 时表达式=m（Kconfig `!m=m`），会把依赖它的 tristate 压回 m——查不到原因时 grep 依赖里的恒真式
2. **BT 固件路径**：dt firmware-name="polaris/crnv21.bin" → 驱动加 qca/ 前缀 → `/lib/firmware/qca/polaris/crnv21.bin`；**不带扩展名的 firmware-name 走另一套 board 拼名逻辑**（btqca.c:879-935）
3. **固件必须 rootfs+initramfs 双放位**（userspace 触发的 setup 读 rootfs）
4. **hcitool scan 在 6.19 必败**（legacy ioctl 弃用）——用 bluetoothctl
5. **apt 断网时**：Windows curl 下 deb → scp → dpkg -i（注意 deb822 源文件里的镜像配置 sed .list 不够，sources.list.d/*.sources 也要）
6. **UNCONFIGURED 锁死**：setup 一次失败即锁，down/up 无效只能重启
7. make 管道吞退出码再踩（v19b）：`make >log; RC=$?` 显式检查
