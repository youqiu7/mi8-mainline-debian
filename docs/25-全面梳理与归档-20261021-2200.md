## 2. WiFi 线：证据链与当前卡点

mpss 死亡演进（每步都有日志留档）：
```
40s fatal（rmtfs 无）→ 14ms 死（rmtfs 通）→ verbose 铁证：
  open 6 个 EFS 全成功 → alloc 2MB 共享内存 → 读 1 扇区(EFS superblock@512) → bye 自杀
→ 空 EFS 同样死 = 内容无关 → 原厂 EFS 也同法死 = 数据排除
→ 死亡地址 0xf6301200（共享内存读回处）→ 头号假设：MPSS 访问该区被 TZ 拦（未经 SCM 授权）
```
**为什么没授权**：该授权本是内核 `rmtfs_mem` 驱动的本职（probe 里 `qcom_scm_assign_mem`），我们用 /dev/mem 绕过它起了 rmtfs——授权链缺失。而 `CONFIG_QCOM_RMTFS_MEM=m` 且设备**无 /lib/modules** → 模块补救路线已走通到 probe 自动绑定 `f6301000.memory`，最终撞 `acpi_bind_one → is_acpi_device_node` **内核 oops**（+ 同源现象：该 reserved-memory 子节点 of 属性读取全部 -EINVAL）→ 深水区止损，细节与手工编模块的 7 个坑全录 **24 号 §3–§4**。

**路线（详见 24 号 §5）**：
- **A（正统，已批）**：内核 `CONFIG_QCOM_RMTFS_MEM=y`（**用上游原版，勿合我 hack patch**）→ 全量重编 → ESP 更新 → modem 再测。**需用户在场。**
- **B（并行，零刷机）**：rmtfs 的 alloc 改返回 SMEM 区地址（0x86000000）——rmtfs 一处常量 patch，验证 TZ 假设。稍后跑。
- mpss 健康后：观察 svc0x45 → wlan0 → 连 **OPPO A5-5G / <WIFI_PASSWORD>** → 更新锚点 → 电池/充电。
