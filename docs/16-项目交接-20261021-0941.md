## 3. 本轮解决的三个真问题

### 3.1 串口 getty 起不来（根因）

journal 硬证据：

```
00:04:56 systemd[1]: Expecting device dev-ttyGS0.device - /dev/ttyGS0...
00:12:26 systemd[1]: dev-ttyGS0.device: Job dev-ttyGS0.device/start timed out.
00:12:26 systemd[1]: Dependency failed for serial-getty@ttyGS0.service - Serial Getty on ttyGS0.
```

`/dev` 是 initramfs 的 devtmpfs 经 `MS_MOVE` 搬进新根，**udevd 没有 trigger 既有节点** → `dev-ttyGS0.device` 不存在 → `serial-getty@`（带 `BindsTo=dev-%i.device`）永不启动。

**修复**：`/etc/systemd/system/ttygs0-console.service`

```
[Service]
Type=simple
ExecStartPre=/bin/sh -c 'for i in $(seq 1 30); do [ -e /dev/ttyGS0 ] && exit 0; sleep 0.2; done; exit 1'
ExecStart=/sbin/agetty --autologin root --noclear --keep-baud 115200,38400,9600 ttyGS0 vt100
Restart=always
```

不依赖 device unit，`agetty` 自己 open 端口。**同时删除** `getty.target.wants/serial-getty@ttyGS0.service`（否则抢端口）。

### 3.2 `console=ttyGS0` 让内核静默

- gadget 是 init（initramfs）创建的，内核启动时 ttyGS0 不存在 → `Warning: unable to open an initial console.`
- 且 `u_serial` 的 console write 是阻塞式的，主机不读时 printk 会卡住
- `systemd.log_target=console` 又让 systemd 日志完全不进 journal → 三重失明

**修复**：cmdline 改为

```
console=tty0 earlycon=qcom_geni ignore_loglevel loglevel=7 log_buf_len=4M fbcon=map:0 acpi=off
```

`CONFIG_CMDLINE_FORCE=y` 保留（内置 cmdline 生效），**不再有 ttyGS0 和 log_target**。

### 3.3 RNDIS → CDC-NCM

- Windows 11 25H2 **已移除 RNDIS 驱动**，RNDIS gadget 枚举出来但 `ProblemCode 28`
- 改用 `ncm.usb0`（`CONFIG_USB_CONFIGFS_NCM=y` / `CONFIG_USB_F_NCM=y` 已内建）
- init v7 的 gadget = `acm.GS0 + ncm.usb0`
- gadget 接口 networkd **不接管**（`Network File: n/a`）→ 用 oneshot 服务固定地址：

```
usb0-static.service: ip link set usb0 up; ip addr add 169.254.1.1/16; ip addr add 10.55.0.1/24
```

Windows 侧借 APIPA `169.254.x.x/16` 与 `169.254.1.1/16` 同网段，**不需要管理员权限配 IP**。

## 5. WiFi 卡点（已定性，非配置漏项）

### 5.1 已就位

- 内核 `CFG80211=y / MAC80211=y / ATH10K=y / ATH10K_SNOC=y / QCOM_QMI_HELPERS=y / QCOM_RPROC_COMMON=y / RPMSG_QCOM_GLINK_SMEM=y / QRTR=y`
- Kconfig 补丁：`QCOM_RPROC_COMMON` `tristate→bool`；`ATH10K_SNOC` `depends on ... || =n` → `select QCOM_RPROC_COMMON`（原版依赖在 6.19 下永远算成 `m`，而本方案无 `/lib/modules`）
- DTS：`&wifi { status="okay"; 5 路供电; }`（vreg_l5a/l7a/l17a/l23a/l25a），dtb `9242721c`（reserved-memory=23 校验通过）
- 固件已在 initramfs（**probe 发生在 switch_root 之前，只放 rootfs 不够**）
- 结果：`ath10k_snoc` 绑定 `18800000.wifi`，`bind_rc=0`，`/sys/bus/platform/devices/18800000.wifi/supplier:*` 有 5 个 regulator

### 5.2 缺什么

- `ath10k_snoc_probe()` 只做 `ath10k_fw_init()` + `ath10k_qmi_init()`；`ath10k_core_register()` 在 **QMI 服务到达回调**（`snoc.c:1369`），所以 probe 成功时**本来就没有日志**
- `ath10k_qmi_init()` 只调 `qmi_handle_init()` + `qmi_add_lookup(WLFW_SERVICE)`，**不创建任何传输层**
- QMI 走 QRTR；QRTR 的 smd 传输匹配 rpmsg 通道 **`IPCRTR`**（`net/qrtr/smd.c`）
- **`/sys/bus/rpmsg/devices/` 为空**；`CONFIG_QRTR_SMD=m`（无模块）
- 全树核对：`arch/arm64/boot/dts/qcom/` 除 ipq 系列外**没有任何平台提供 IPCRTR**；`sdm845.dtsi` 只有 `apss_shared: mailbox@17990000`，**无 wcss smp2p、无 wcss remoteproc**
- pmOS 实际使用的 `sdm845-mainline/linux` **sdm845-6.11 tag**（APKBUILD 无本地补丁）：`sdm845.dtsi` 5971 行，wifi 节点与 6.19 **逐字相同**，同样没有 IPCRTR/smd-edge/wcss_smp2p
- pmOS wiki 对 beryllium（同 SDM845）的 WiFi 标注 = **Partial**

### 5.3 若要继续

1. **力搏 DT**：在 `&wifi` 加 `glink-edge { qcom,glink-channels = "IPCRTR"; mboxes = <&apss_shared ...>; }` + 自建 wcss smp2p。无上游参考，成功率未知；失败可一条命令回滚 ESP 到 `00b17e15`
2. 移植 pmOS/厂商的 sdm845 wcss QMI 补丁
3. 接受 USB 网络作为服务器通道（当前方案）

## 8. 自动化链路（本轮最大效率提升）

```bash
# 任意状态 → Android → 写 ESP（可选 rootfs）→ 引导 → 串口自检
bash 02-工具/83-auto-cycle.sh --efi C:/Users/duoya/AppData/Local/Temp/mi8flash/BOOTAA64-xxx.efi
bash 02-工具/83-auto-cycle.sh --efi <efi> --rootfs /root/rootfs-4g.img
```

- 设备在 Linux：串口 `sync;reboot` 自动回 Android（**无需人工按键**）
- 设备在 fastboot：`erase misc` + reboot
- 写盘双重 md5 校验；引导后自动等 COM + `echo AUTO_OK_n` 确认 shell

## 11. 本轮新增教训

| # | 教训 |
|---|---|
| 1 | **`serial-getty@` 依赖 device unit**；initramfs 搬来的 `/dev` 不经 udev trigger 时它永不启动。自定义 service 直接 `agetty ttyGS0` 才可靠 |
| 2 | **`console=ttyGS0` 是毒参数**：gadget 未建立时内核 `unable to open an initial console`，写 console 还会阻塞 |
| 3 | **`systemd.log_target=console` 会让 systemd 日志完全不进 journal**，调试期必须改成 journal 或不设 |
| 4 | **Win11 24H2+ 移除 RNDIS**（`ProblemCode 28`），USB 网络必须用 CDC-NCM |
| 5 | **gadget 网卡 networkd 不接管**（`Network File: n/a`），用 oneshot 服务或 udev 规则配地址 |
| 6 | **ath10k 的 probe 成功≠有 wlan0**：`ath10k_core_register` 在 QMI 回调里，probe 静默是正常的 |
| 7 | **WiFi 固件必须进 initramfs**：probe 在 switch_root 之前，只放 rootfs 会 ENOENT 且无日志（早期 dmesg 会被刷掉）|
| 8 | **`mount -o loop` 默认 rw 会改 md5**：核查镜像必须 `-o ro,noload` |
| 9 | **Android 侧 `mount -t ext4` rw 会 EINVAL**：改盘只能整镜像 dd |
| 10 | **`wsl.exe -c '...$VAR...'` 不展开变量**：写 `.sh` 文件再执行（本轮踩了 3 次）|
| 11 | **adb push 到 root 拥有的目录 Permission denied**：先 push `/data/local/tmp/`，再 `su -c cp` |
