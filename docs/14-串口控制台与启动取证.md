## 一、问题定义

设备能完成 `UEFI → 内核 → init → switch_root → systemd`（journal 有证据），但 PC 端串口 `COM7`：

- 读：150 秒窗口 **0 字节**
- 写：`WriteFile` 返回 `ERROR_SEM_TIMEOUT (121)`，连续 3 次
- 无 UMS 盘符（说明 init 没进诊断模式）
- `adb`/`fastboot` 均为空（说明不在 Android）

`err=121` 的含义是决定性的：**设备端 CDC-ACM 端点没有读者**，不是主机读取工具的问题。

## 二、三次启动的对照（唯一变量法）

| # | 时间 | ESP 内 EFI | 内核 cmdline 来源 | rootfs 版本 | 结果 |
|---|---|---|---|---|---|
| 1 | 03:15 | `deb0b27b` | UEFI 提供（**无** `console=ttyGS0`） | 340125ab（旧） | journal：systemd 完整启动，sshd 监听 0.0.0.0:22；串口无 login（旧 rootfs 未启用 getty） |
| 2 | 04:05 | `0c25619f` | 内置 `CMDLINE_FORCE`，**含** `console=ttyGS0` | 5d8cf777 | 串口 0 字节；journal 有记录但**没有 `systemd[1]` 消息**（因为 `systemd.log_target=console`） |
| 3 | 04:18 | `0c25619f` | 同上 | 72801274 | 串口 0 字节；**sda23 上一个新日志字节都没有**（systemd 未写 journal） |
| 4 | 04:27 | `deb0b27b` | UEFI（无 ttyGS0） | 72801274 | 串口 0 字节，写 `err=121` |

**结论 1**：`console=ttyGS0` 会让启动更早死（第 3 次连 journald 都没到）——内核 console 写 `u_serial` 是阻塞式的，主机未打开端口时 printk 卡住。
**结论 2**：但去掉 `console=ttyGS0`（第 4 次）后串口仍然无人打开 → 还有第二个独立问题：**systemd 没把 getty 拉到 ttyGS0 上**。

## 三、根因分析

### 3.1 为什么 journal 里看不到 systemd 消息

内核 cmdline 含 `systemd.log_target=console`。该参数**覆盖** `/etc/systemd/system.conf` 的 `LogTarget`，让 systemd 自己的日志只写 console、不进 journal。
再叠加“console = 不亮的 tty0 / 无人读的 ttyGS0”，等于把 systemd 的日志全丢。
→ 后续必须去掉这个参数（或改为 `journal`）。

### 3.2 为什么首次启动要等 11 分钟

`/var/log/journal` 的 boot 0：

```
08:00:01 systemd-random-seed[189]: Kernel entropy pool is not initialized yet, waiting until it is.
（以下 11 分钟无任何条目）
08:11:06 systemd-timesyncd[190]: System clock time advanced to recorded timestamp
08:11:07 kernel: random: crng init done
08:12:37 sshd[238]: Server listening on 0.0.0.0 port 22.
```

rootfs 里没有 `/var/lib/systemd/random-seed`，而 sdm845 的 `rng` 驱动没有 probe（`sync_state() pending due to 793000.rng`），熵池 11 分钟才就绪。
→ 修复：预生成 seed 文件 + mask `systemd-random-seed.service`（已做）。

### 3.3 为什么 getty 没起（当前主要假设）

`serial-getty@ttyGS0.service` 属于 `getty.target`，而该模板服务带：

```
BindsTo=dev-%i.device
After=dev-%i.device
```

我们的 `/dev` 是 initramfs 里的 devtmpfs 通过 `MS_MOVE` 搬进新根的，systemd-udevd 启动后**没有对既有节点做 trigger**，所以 `dev-ttyGS0.device` 单元可能不存在 → `serial-getty@ttyGS0` 永不启动。

证据支持：
- `/dev/ttyGS0` 节点存在（gadget 由 init 配置，USB 已枚举）
- 主机写入 `err=121`（无人 open 该 tty）
- 未进诊断模式（UMS 无盘符）→ init 已 `switch_root`，systemd 应在运行

**这是待验证假设**：需要本次启动的 journal 里 `dev-ttyGS0.device` / `serial-getty@ttyGS0` 的记录来确认。

## 四、修复设计（rootfs `70a4d071`）

### 4.1 不依赖 device unit 的串口控制台

`/etc/systemd/system/ttygs0-console.service`：

```
[Unit]
Description=Serial console on ttyGS0 (udev-independent)
After=local-fs.target systemd-udevd.service
StartLimitIntervalSec=0

[Service]
Type=simple
ExecStartPre=/bin/sh -c 'for i in $(seq 1 30); do [ -e /dev/ttyGS0 ] && exit 0; sleep 0.2; done; exit 1'
ExecStart=/sbin/agetty --autologin root --noclear --keep-baud 115200,38400,9600 ttyGS0 vt100
Restart=always
RestartSec=2

[Install]
WantedBy=multi-user.target
```

要点：
- 不写 `BindsTo`，不依赖 `dev-ttyGS0.device`
- `agetty` 自己 `open("/dev/ttyGS0")`，绕过 systemd 的 tty 管理
- `Restart=always`：即使早期打不开，2 秒后重试
- 同时删除 `getty.target.wants/serial-getty@ttyGS0.service`，避免两个进程抢同一个 tty

### 4.2 开机自证（不依赖串口）

`proof.service` → `/usr/local/sbin/proof.sh`，开机把以下内容写 `/var/log/proof.log`：

- `/proc/uptime`、pid 1 命令行
- `/dev/ttyGS0` 节点与权限
- `dev-ttyGS0.device` 是否存在
- `systemctl status getty.target` / `ttygs0-console.service`
- `udevadm info /dev/ttyGS0`
- 向 ttyGS0 写入测试（带 3 秒 timeout，避免阻塞）
- 失败单元列表、运行中的服务、agetty 进程

这样即使串口完全不通，也能从 Android 侧挂载 sda23 读到“卡在哪”。

### 4.3 已包含的前置修复

- `/var/lib/systemd/random-seed`（512B）+ mask `systemd-random-seed.service` → 不再等熵池
- `default.target` → `multi-user.target`（原来是 `graphical.target` fallback）
- `first-boot.sh` 融合版：时区、`resize2fs` 扩容、网络服务；**去掉 `apt-get update`**（无 WiFi 驱动时会长时间阻塞）
- `sshd_config`：`PermitRootLogin yes` / `PasswordAuthentication yes`

3. journal 里 `ttygs0-console.service` / `dev-ttyGS0.device` 的状态

## 六、已知陷阱（新增）

1. **`wsl.exe -c '...'` 不展开变量**：必须写成 `.sh` 文件再执行（本轮又踩一次）
2. **`mount -o loop` 默认 rw**：核查镜像必须 `-o ro,noload`，否则 md5 变化（本轮把 `5d8cf777` 改成 `1f823b89`）
3. **Android 侧 `mount -t ext4` rw 失败（EINVAL）**：只能 `-o ro,noload` 读，改盘必须走 dd 整镜像
4. **adb push 到 root 拥有的目录会 Permission denied**：先 push 到 `/data/local/tmp/`，再 `su -c cp`
5. **`systemd.log_target=console` 会让 systemd 日志完全不进 journal**：调试期必须改成 `journal`
6. **`serial-getty@` 依赖 device unit**：initramfs 搬过来的 `/dev` 没经过 udev trigger 时不会启动
