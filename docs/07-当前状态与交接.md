## 一、已达成（P1 通关）

**eq uuleus 上第一次跑通主线 Linux 并能在屏幕上看到内核日志。**

```
ABL → EDK2 UEFI (boot-equuleus.img, edk2-msm 2301.1)
     → ESP:/EFI/Boot/BOOTAA64.EFI（= 内核 Image + 尾部 equuleus DTB）
     → 内核 EFI stub（用 UEFI GetMemoryMap，不依赖 UEFI 的 DTB）
     → 读 Image 尾部 DTB → sdm845 平台驱动 probe
     → USB CDC-ACM gadget 成功 → COM6
```

关键里程碑证据：

| 证据 | 说明 |
|---|---|
| 屏幕滚动内核日志 | simplefb/efifb 工作，显示通路打通 |
| `[init] alive 30s / 60s / …` 持续心跳 | 内核进了 userspace，initramfs 正常 |
| Windows 出现 **COM6**（USB CDC-ACM） | **dwc3 probe 成功 = `acpi=off` 生效 = 我们的 DTB 被采用** |
| `pstore: Registered efi_pstore` | 以后 panic 日志可持久化到 ESP |

### 走过的大坑（都已定位并解决）

| 坑 | 结论 |
|---|---|
| `fastboot boot` 黑屏/关机（v1、v2） | ABL 的 appended-dtb 机制我们无法可靠驾驭；pmOS 官方对该机型也是 `screen=N` |
| GRUB 报 `error: no memory definition.` | **edk2 固件不提供 DTB**，GRUB 在 arm64 要靠 DTB 建内存映射，必然失败 |
| 内核起来但屏幕黑、驱动全无 | 用 EFI 启动时**内核默认走 ACPI**，忽略 appended DTB → 必须 `acpi=off` |
| 串口发 `r` 设备不重启 | CDC-ACM 默认 canonical 行缓冲，**必须带回车**（`r` + `\r`） |
| `adb reboot bootloader` 后设备关机 | MIUI/ABL 在该 USB 口下 fastboot 枚举不稳定（最早出现过 "press any key to shutdown"） |

### 为什么要刷到 recovery 而不是 boot

- `boot` 分区保持原样 → **普通开机仍然进 Android**（符合 D1「保留 Android」）
- `recovery` 分区拿来放 UEFI → **「音量上 + 电源」= 进 Linux**
- 原 recovery 已备份：`03-备份/bk_recovery.img`（md5 `b5198af3…`），一条命令可回滚
- 这样以后测试**只需要音量上+电源**，不再需要电脑发 fastboot 命令
