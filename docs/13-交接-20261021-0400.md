## 3. 本轮修复的 4 个真 bug

### 3.1 `pivot_root` 在 initramfs 必然 EINVAL

内核 `fs/namespace.c`：

```c
if (!mnt_has_parent(root_mnt))
    return -EINVAL; /* absolute root */
```

initramfs 的 `/` 是 **rootfs = absolute root（无 parent）**，`pivot_root` 对它必然失败。设计如此。

**改用标准 switch_root**：

```c
mount(NULL, "/", NULL, MS_REC | MS_PRIVATE, NULL);  // source 必须 NULL，"" 会 EINVAL
chdir(NEWROOT);
mount(".", "/", NULL, MS_MOVE, NULL);
chroot(".");
chdir("/");
execl("/sbin/init", "/sbin/init", NULL);
```

### 3.2 `errno` 被 `strerror()` 改写 → 假错误码

```c
printf("%s\n", strerror(errno));       // ❌ 打印的是 strerror 自己产生的 errno
int saved = errno;                      // ✅ 先存
printf("errno=%d (%s)\n", saved, strerror(saved));
```

曾因此误判 `EAGAIN=11`，而内核对 pivot_root 从不返回 EAGAIN。

### 3.3 `getty.target` 未启用

`getty.target.wants/serial-getty@ttyGS0.service` 存在，但 `multi-user.target.wants/` 里**没有 `getty.target`** → systemd 从不拉 getty。

```bash
ln -sf /lib/systemd/system/getty.target /etc/systemd/system/multi-user.target.wants/getty.target
rm -f /etc/systemd/system/serial-getty@ttyGS0.service.d/override.conf   # 与 autologin 冲突
```

### 3.4 【最关键】cmdline 被 bootloader 覆盖

```
CONFIG_CMDLINE="console=tty0 console=ttyGS0 ... acpi=off"
CONFIG_CMDLINE_FROM_BOOTLOADER=y    ← 内置 cmdline 完全失效
```

`FROM_BOOTLOADER=y` 时内核丢弃 `CONFIG_CMDLINE`，只用 UEFI 传的 cmdline。UEFI 那份**没有 `console=ttyGS0`**：

- init 心跳可见 → init 自己 `dup2(ttyGS0, 1)`
- **systemd 日志看不到 → 写到内核 console = `tty0` = 不亮的屏**

**修复**（6.19 无 `CMDLINE_BOOL`，正确开关是 `CMDLINE_FORCE`）：

```
# CONFIG_CMDLINE_FROM_BOOTLOADER is not set
CONFIG_CMDLINE_FORCE=y
CONFIG_CMDLINE="console=tty0 console=ttyGS0 earlycon=qcom_geni ignore_loglevel loglevel=8 fbcon=map:0 acpi=off systemd.log_target=console systemd.log_level=info"
```

已用 `olddefconfig` 复验：三行不被冲掉，`ARCH_QCOM=y` / `SCSI_UFS_QCOM=y` 完好。

## 4. 踩过的坑

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | **`make olddefconfig` 重置 config** | 改完必须复核 `ARCH_QCOM`/`SCSI_UFS_QCOM`/`CMDLINE*`。曾把 `ARCH_QCOM` 整个关掉，编出 23 MB 废内核 |
| 2 | **Android `toybox dd` 的 `seek=` 会 ftruncate 块设备失败** | 必须 `conv=notrunc`，否则只有第一块写进去 |
| 3 | **`adb.exe` 不认 MSYS 路径** | 传 `C:/Users/...`，不是 `/c/Users/...` |
| 4 | **`wsl.exe -c` 里变量不展开** | 写成 `.sh` 文件再执行 |
| 5 | **C: 盘会满** | 写盘前 `Get-Volume` 查空间，Windows 侧副本用完即删 |
| 6 | **UMS 写 ESP 不可信**（Windows 缓存） | 用 `adb push` + 设备端 `md5sum` 回读 |
| 7 | **cmdline 绝不能带 `dtb=`** | 带它 panic；`DT model` 显示 Mi MIX 2S 是正常的 |
| 8 | **dtb 必须完整**（`reserved-memory`=23、nodes 808） | `cpp` 带 `-I scripts/dtc/include-prefixes`，`dtc` 带 `-@`，禁止 `2>/dev/null` |
| 9 | **`fastboot boot <内核>` 本机从不成功** | 只有 UEFI 路径能引导 |
| 10 | **串口句柄泄漏** | `Disable-PnpDevice` / `Enable-PnpDevice` 重置 |

## 9. init 行为（init_v5.c）

```
mount proc/sys/dev
  → 探测挂 sda23（ext4 rw，成功则保留）
  → 配 gadget（CDC-ACM；rootfs 不可用时额外暴露 UMS sda22+sda23）
  → 打开 /dev/ttyGS0，dup2 到 1/2
  → try_switch_root():
        make-rprivate / 和 /newroot（source 必须 NULL）
        move /proc /sys /dev 进新根
        chdir(NEWROOT) → mount(".", "/", MS_MOVE) → chroot(".") → chdir("/")
        execl("/sbin/init")
  → 失败 → 诊断模式（心跳 + r/d/m）
```

**判断标准**：`switch_root` 那几句 printf 打在 T+30s（COM7 常还没连上），看不到是正常的。**"心跳消失 + `m` 无响应"才是切根成功的判据。**
